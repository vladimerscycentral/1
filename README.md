# Pocket AI 1.2

Android-приложение восстановлено из предоставленного APK 1.1 (`dev.pocketai`, minSdk 26, targetSdk 35). Это восстановленный проект для дальнейшей разработки. История, инструкция и черновик старой версии переносятся в первый чат при обновлении с той же подписью. API-ключи продолжают храниться через прежний Android Keystore alias.

## Возможности

- Вкладки чатов: создание, переключение, переименование, удаление, экспорт. Истории, инструкции и черновики раздельные. Одна задача выполняется за раз; переключение вкладок сохраняет результат в исходном чате.
- Chat Completions API, список моделей, пресет OpenRouter, локальный HTTP для Ollama в частной сети, библиотека промптов.
- Подключение GitHub через personal access token: проверка аккаунта и ветки, выбор workflow, ссылка на сборки и артефакты.
- ИИ может читать, создавать и редактировать текстовые файлы в выбранной системным диалогом папке телефона или указанном GitHub-репозитории. Перед перезаписью проверяется версия: hash для локального файла, sha для GitHub. GitHub-запись создаёт отдельный коммит.
- Авторежим выполняет последовательность действий и передаёт результаты модели без отдельных подтверждений. Ручной режим с подтверждениями сохранён. Есть журнал и Стоп.
- `github_build` запускает выбранный workflow, `github_runs` показывает статус и SHA сборок, `github_jobs` — этапы и ссылки. Запрос запуска не считается успешной сборкой.

## Настройка на телефоне

1. В «Подключение» укажи адрес API, API-ключ и модель.
2. В «GitHub, файлы и авторежим» укажи `owner/repo`, существующую ветку и свой GitHub-токен. Выбери только нужный репозиторий; права Contents: Read and write, Actions: Read and write. Для редактирования `.github/workflows` нужно Workflows: Read and write. Токен вводится на телефоне, шифруется и не отправляется модели.
3. Нажми «Проверить GitHub и загрузить workflows», выбери workflow. Он должен поддерживать `workflow_dispatch` и присутствовать в основной ветке репозитория. Сохрани настройки и включи доступ к GitHub.
4. Для локальных файлов выбери папку, включи доступ и сохрани. Если нужны автоматические изменения, включи «Выполнять действия ИИ автоматически».
5. Пример задания: «Прочитай структуру репозитория, измени …, создай коммит и запусти сборку. Проверь статус и сообщи ссылку».

## Сборка

Нужны JDK 17, Android SDK Platform 35 и Build Tools 35.0.0.

```sh
export ANDROID_HOME=/path/to/android/sdk
bash gradlew testDebugUnitTest lintDebug assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`. Wrapper использует Gradle 8.11.1 с SHA-256. Workflow `.github/workflows/android.yml` выполняет те же проверки и публикует artifact `pocket-ai-debug`. По умолчанию используется локальная debug-подпись Android; для обновлений установленного приложения нужна прежняя подпись. Для стабильной подписи сборок Actions настрой GitHub Secrets `POCKET_SIGNING_KEYSTORE_BASE64`, `POCKET_SIGNING_STORE_PASSWORD`, `POCKET_SIGNING_KEY_ALIAS`, `POCKET_SIGNING_KEY_PASSWORD`. Локальная сборка принимает `POCKET_SIGNING_STORE_FILE` и три соответствующие переменные пароля/alias. Секреты не добавляются в исходный код. Загруженный ранее keystore в публичном репозитории не используется workflow автоматически.

## Проверки

Unit-тесты охватывают перенос истории, раздельность вкладок, восстановление состояния, UI, границы путей, разрешённые адреса API, автоматическую цепочку, её остановку и предел 24 действий, запрет повторной записи при неопределённом результате, GitHub sha-конфликты, адреса веток и workflow dispatch/status. `GitHubEmulatorTest` дополнительно запускается при `POCKET_GITHUB_EMULATOR_URL` и проверяет чтение/создание/редактирование через закреплённый CodeRabbit emulate v0.0.1 с синтетическим репозиторием; без переменной этот внешний тест пропускается. Протокол сборок проверяется отдельными HTTP fixtures: данный эмулятор не обнаруживает workflows из записанных файлов. Эмулятор не собирает настоящий APK.

## Ограничения

Держи приложение открытым во время задачи: фонового сервиса нет. Одновременно выполняется одна задача, максимум 24 действия и 10 минут на запуск. Остановка прекращает последующие действия; уже отправленный коммит или сборка могут завершиться на сервере. После ошибки записи сначала проверь реальное состояние. Текстовые файлы ограничены 24000 символами, история — 100 сообщениями, контекст модели — 20 последними сообщениями. Качество изменений зависит от выбранной модели. Полные CI-логи и APK доступны по ссылке GitHub Actions; автоматической установки APK и чтения полного ZIP-журнала нет. Для реального подключения нужны настройки пользователя на телефоне.
